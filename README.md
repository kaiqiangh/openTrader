## Overview

**Open Trader** is a multi-exchange crypto trading platform powered by LLM agents. Decisions are generated by a multi-agent orchestration layer (Planner, Risk, Execution) combining real-time market microstructure with news intelligence.

- **Python 3.13+**: Agentic strategy, orchestration, data ingestion.
- **Go**: Ultra-low-latency order execution.
- **Deterministic Risk**: Position limits, drawdown protection, daily loss limits, circuit breakers.

## Key Features

- **Agentic Strategy Engine**: Multi-agent runtime with Planner, Risk, and Execution agents + short/long-term memory.
- **Dual Trading Modes**: `MOCK` (simulated fills) and `REAL` (exchange execution) with hard mode isolation.
- **Multi-Exchange Ingestion**: Binance + Bitget via REST polling or websocket.
- **News Intelligence**: Crypto news ingestion, summarization, sentiment analysis injected into agent context.
- **Institutional Risk**: Drawdown protection, daily loss limits, leverage validation, circuit breakers, kill switch.
- **Observability**: Per-worker Prometheus `/metrics` (ports 8081-8086), structured JSON logging, W3C trace propagation.
- **Multi-Channel Notifications**: Telegram, Email (SMTP), Webhook — with retry, dedup, and DLQ.
- **JWT Refresh Tokens**: 15-min access tokens + 7-day refresh rotation with Redis revocation.
- **Redis Rate Limiting**: Sliding window with automatic in-memory fallback.
- **RS256 Only**: RSA-signed JWT. No HS256 fallback.

## Quick Start

```bash
# 1. Clone
git clone https://github.com/kaiqiangh/openTrader.git
cd openTrader

# 2. Configure
cp .env.example .env
# Edit .env — at minimum set:
#   ENCRYPTION_KEY_BASE64 (AES-256-GCM key, 32 bytes base64)
#   JWT_PRIVATE_KEY + JWT_PUBLIC_KEY (RS256, generate: uv run python scripts/generate_token_rs256.py --user-id admin --role admin --gen-key)

# 3. Validate
make env-validate

# 4. Launch
docker compose up -d

# 5. Check health
curl -s http://127.0.0.1:8000/health/liveness | python3 -m json.tool

# 6. Open dashboard
open http://localhost:3000
```

## Architecture

```
Exchanges → Market Ingestion → RabbitMQ → Agent Orchestrator
                                              ├─ Planner Agent
                                              ├─ Risk Agent
                                              └─ Execution Agent
                                                       ↓
                                          Risk Gate (guardrails)
                                                       ↓
                                    ┌─────────────────┴─────────────────┐
                              Mock Execution                    Real Execution (Go)
                                    ↓                                     ↓
                                    └─────────────→ OMS ←───────────────┘
                                                      ↓
                                            PostgreSQL + TimescaleDB
                                                      ↓
                                            API ← Dashboard (Next.js)
                                                      ↓
                                         Notifications (Telegram/Email/Webhook)
```

## Services

| Service                              | Purpose                                                         |
| ------------------------------------ | --------------------------------------------------------------- |
| `market_ingestion`                   | Exchange adapters, normalization, integrity                     |
| `agent_orchestrator`                 | Multi-agent decision orchestration, guardrails, replay          |
| `llm_gateway`                        | Provider abstraction, quotas, prompt/response persistence       |
| `simulation_execution`               | Mock execution engine with slippage/fees                        |
| `real_execution_go`                  | Low-latency Go order execution                                  |
| `oms`                                | Order lifecycle, fill reconciliation, positions, risk rules     |
| `news_ingestion` + `news_summarizer` | Crypto news pipeline                                            |
| `notification_service`               | Policy routing, Telegram/Email/Webhook gateways                 |
| `api`                                | FastAPI control plane, auth, ops/governance/replay routes       |
| `tasks`                              | Celery: portfolio rollup, news backfill, data retention, digest |

## Observability

- **Metrics**: API at `/metrics` (port 8000), each worker at `/metrics` (ports 8081-8086)
- **Logs**: JSON structured with `trace_id`, `decision_id`, `strategy_id`, `mode`, `service`
- **Traces**: W3C `traceparent` header propagation
- **Dashboards**: Grafana configs in `config/observability/`
