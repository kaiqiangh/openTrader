# Continuous Learning - P8 Observability Stack + Key Encryption (2026-02-14)

## Session Context

- Implemented `P8-004`, `P8-005`, and `P8-006` covering compose observability stack, critical alert rules, and AES-256-GCM exchange key protection at rest.

## Learned Instincts

1. Wire stack config and compose together in the same turn.
   - Keeping service definitions and config file additions synchronized avoids deployment drift and flaky startup behavior.

2. Alert catalogs should be explicit even before metric maturity.
   - Stable alert names and annotations provide operational contracts early, while threshold tuning can happen later with real telemetry.

3. Encrypt-at-rest work needs both crypto correctness and persistence boundary tests.
   - Round-trip, tamper detection, and plaintext-leak assertions in DB rows catch most practical regressions quickly.

4. Environment validation should enforce cryptographic key shape.
   - Base64 + exact 32-byte checks prevent silent runtime failures in AES-256-GCM initialization.

5. Keep security primitives centralized in shared runtime modules.
   - A single encryptor/store contract makes future API and worker integrations simpler and safer.

## Follow-Up Candidates

- Add key-rotation support (`v2` payload version + dual-decrypt window) for encrypted exchange credentials.
- Add compose smoke tests that bring up observability profile and verify endpoint readiness automatically.
