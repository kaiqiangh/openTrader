## Task 2: SEC-019 — Tighten Fill Reconciliation Fallback

**Context:** `_requires_fallback` in `services/oms/fill_reconciliation.py` triggers fallback when exchange snapshot shows more fills than queue. But this can happen due to timing lag — the queue will catch up. We should only fallback when the exchange has terminal state OR the fill gap is significant (not just rounding).

**Current code (lines 177-191):**
```python
if current_status not in TERMINAL_STATES:
    if normalized_snapshot_status in TERMINAL_STATES:
        return True
    if snapshot_filled > (queue_filled + _EPSILON):
        return True
    return False
```

**Fix:** Add a minimum gap threshold — only fallback when snapshot shows MORE fills that are actually meaningful (not just 1e-9 epsilon). Use a larger threshold like 0.001 to account for floating point noise.

**Files:**
- `services/oms/fill_reconciliation.py` — `_requires_fallback` function

**Steps:**
1. Write failing test showing false fallback trigger
2. Add minimum gap threshold
3. Run existing reconciliation tests
4. Commit

## Task 3: CQ-004 — Standardize Quantity Epsilon Validation

**Context:** `services/oms/risk_rules.py` uses `_EPSILON = 1e-9` for quantity checks. `services/api/internal_execution/adapters.py` uses `quantity <= 0` without epsilon. This inconsistency means a quantity of 1e-10 passes one check but fails another.

**Current code in adapters.py line 445:**
```python
if quantity <= 0:
    raise InternalDispatchValidationError("quantity must be positive for create operation")
```

**Fix:** Use consistent epsilon comparison: `quantity < 1e-9` instead of `quantity <= 0`.

**Files:**
- `services/api/internal_execution/adapters.py:445` — `validate_create_order_fields`

**Steps:**
1. Write failing test for edge case (quantity = 1e-10)
2. Update validation to use epsilon
3. Run tests
4. Commit
