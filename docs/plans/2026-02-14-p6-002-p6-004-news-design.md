# Phase 6 News Pipeline Design (P6-002 to P6-004)

## Scope

Deliver the next three Phase 6 tasks in sequence:

- `P6-002`: ingestion service with normalize + dedupe + persistence
- `P6-003`: tagging and relevance scoring pipeline
- `P6-004`: rolling summarizer service

## Context

- `P6-001` source connector framework already exists in `services/news_ingestion/source_connectors.py`.
- News schema tables already exist (`news_items`, `news_tags`, `news_summaries`).
- Downstream context injection (`P6-005`) is intentionally out of scope for this turn.

## Approaches Considered

### Option A (Recommended): Deterministic service modules with store protocols

- Add service modules with explicit dataclasses + protocols and in-memory stores for deterministic testing.
- Keep heuristics simple and bounded (keyword-based relevance/sentiment).
- Summarizer generates stable rolling-window artifacts without LLM dependency.

Pros:
- Fast, testable, and aligned with contract-first architecture.
- Easy to replace with DB adapters and LLM summarization later.

Cons:
- Heuristic quality is baseline-level, not production NLP quality.

### Option B: Direct SQLAlchemy implementation now

Pros:
- More runtime-like persistence.

Cons:
- Larger scope and coupling for this phase step.
- Harder to keep unit tests fast and deterministic.

### Option C: LLM-first summarization now

Pros:
- Better summary fluency.

Cons:
- Adds cost/latency dependency before ingestion/tagging baseline is stable.

## Selected Design

Option A.

### Module boundaries

- `news_ingestion/ingestion_service.py`
  - Normalize source records.
  - Compute canonical content hash.
  - Dedupe by `(source, source_item_id)` and by `hash`.
  - Persist via `NewsItemStore` protocol.

- `news_ingestion/tagging_relevance.py`
  - Rule-based symbol/topic tagging.
  - Relevance and sentiment scoring in `[0, 1]` and `[-1, 1]`.
  - Persist tags via `NewsTagStore` protocol.

- `news_summarizer/summarizer_service.py`
  - Build rolling summaries per scope/window.
  - Select top relevant tagged items.
  - Persist summaries via `NewsSummaryStore` protocol.

### Data flow

1. Connector framework fetch cycle -> source records.
2. Ingestion service normalizes, dedupes, persists `news_items`-compatible records.
3. Tagging pipeline annotates items with symbol/topic/relevance/sentiment and persists tags.
4. Summarizer reads tagged items and persists rolling summary artifacts.

### Error handling

- Invalid record contracts raise typed errors.
- Dedupe collisions become non-fatal skip outcomes.
- Summarizer returns `news_unavailable` fallback text on empty windows.

### Testing

- Unit tests per new module.
- Doc tests for module mentions and plan status updates.

## Success Criteria

- `P6-002`, `P6-003`, `P6-004` marked `DONE` in `docs/IMPLEMENTATION_PLAN.md`.
- New tests green, full suite and lint green.
- README and runtime docs reflect new baseline modules.
